# Provenance and privacy boundary

The contribution contains project-authored C/Thumb/Python source, English documentation, compatibility metadata and aggregate validation results, under GPLv3 as identified in [LICENSE.txt](LICENSE.txt). It references external toolchains and proprietary inputs through [provider links and hashes](DEPENDENCIES.md). No proprietary ROM/RAM/kernel/loader/SDK binary, compiled object, signed executable or foreign instruction-byte dump is distributed here. The full candidate is derived privately from the owner's stock file; the runtime scope is not embedded in it.

The partial live-ROM digest identifies an overlaid view, not a virgin mask-ROM image. ROM/kernel inputs were used to investigate contracts but are not required by the fixed-profile builder. Real network/client addresses, SSIDs, coordinates, credentials, nonce/MIC, raw captured packets, boot-session identifiers, private machine paths/logs and the private application/database/SDK archive are excluded. Only explicit synthetic reader/test fixtures and generic documented target-system paths occur in source.

The actual external-client exchange was independently audited from original private bytes, without importing the collector parser. Public aggregates cannot independently re-audit those withheld bytes and are not password-recovery/MIC-recomputation evidence. The public-source native/bootstrap/standalone control was separately tested; the thirty-second run contained no new handshake. The source builder independently reproduced the exact validated image. Five/fifteen-minute product lifecycle checks are separate from packet-content evidence.

Module bodies originate in the local project implementation. Added SPDX comments, translated diagnostic messages and configurable standalone tool paths do not purport to be copied Apple/Nexmon source. The narrow linker and assembly composition are project-authored; ARM relocation semantics follow the published ABI. Upstream placement, review and future target portability remain maintainer decisions, not claims of acceptance.

The verifier checks an exact inventory, UTF-8/nonbinary content, privacy patterns and optional private-context values, links, hashes and complete ZIP readback. Explicit synthetic self-test strings and fixed generic system paths are narrowly allowlisted. It cannot determine every possible secret, legal right or hardware behavior. Binary build outputs and runtime private files must remain outside this source tree.
